每个机器人都是一个独立频道。消息可以带一张 Telegram 格式的 HTML 卡片，内容可以端到端加密。iOS 走 APNs，Android 走 FCM，网关是一个 Go 二进制加一个 SQLite 文件。 Each bot is its own channel. A message can carry a Telegram-style HTML card, and its content can be end-to-end encrypted. iOS through APNs, Android through FCM; the gateway is one Go binary and one SQLite file.

在 App 里新建机器人，拿到 <bot id>:<secret> 形式的令牌。接口沿用 Telegram Bot API 的命名和 {"ok":…} 信封，参数可以放在查询串、表单或 JSON 里。也可以直接用网关自带的 honk 命令行。 Create a bot in the app and get its token, <bot id>:<secret>. The API keeps Telegram's Bot API naming and {"ok":…} envelope; parameters go in the query string, a form or JSON. Or use the honk command line that ships in the same binary.

端到端加密End-to-end encryption

了解Learn ↗

按机器人开启。发送方用 AES-256-GCM 封装内容，网关只存密文，推送里也没有标题、正文和机器人名，横幅在手机解密后生成。Turned on per bot. The sender seals the content with AES-256-GCM; the gateway stores only ciphertext, and pushes carry no title, body or bot name: the banner is built on the phone after decrypting.

多设备组Device groups

了解Learn ↗

用 26 位配对码把几台手机连成一组，共享机器人和队列。每条消息推给组里每台设备，各自有游标和确认水位，慢的那台也不会丢消息。A 26-character pairing code joins phones into a group that shares bots and the queue. Every message goes to every device, each with its own cursor and ack watermark, so a slow phone never loses one.

一条消息的旅程，推送里只有横幅A message's journey: the push carries only the banner

网关把消息放进短期队列，推送只带横幅文字和 msg_id。手机上的通知扩展再去拉完整消息（卡片在内），所以卡片不受 APNs/FCM 4 KB 载荷的限制。The gateway queues the message and the push carries only the banner text and the msg_id. The notification extension on the phone fetches the whole message, card included, so cards are not bound by the 4 KB APNs/FCM payload.

不丢消息Nothing lost

推送只是提醒，消息在队列里保留 7 天。推送失败会重试，没收到的设备打开 App 时从 /v1/sync 补齐。A push is only a nudge; the message stays queued for 7 days. Failed pushes are retried, and a device that missed one catches up from /v1/sync.

原地更新Updates in place

同一个 id 的新消息替换旧的，editMessageData 只改卡片数据，deleteMessage 连通知一起撤回。A message with the same id replaces the last one, editMessageData changes only the card's data, and deleteMessage takes back the notification too.

卡片会说话Cards talk back

带 allow_queries 的卡片可以 request()，网关把它交给机器人（webhook 或 getUpdates），等 answerWidgetQuery 的回答。A card sent with allow_queries can call request(); the gateway hands it to the bot (webhook or getUpdates) and waits for answerWidgetQuery.

随处部署Runs anywhere

纯 Go、无 cgo 的 SQLite，docker compose up 就能跑。这个页面和 API 文档也打包在同一个二进制里。Pure Go with cgo-free SQLite; docker compose up and it runs. This page and the API docs are in the same binary.

不需要推送证书No push credentials needed

没有 APNs/FCM 凭据的网关会经官方推送中继发送，中继默认只拿到推送令牌和 id，看不到横幅文字。A gateway without APNs/FCM credentials pushes through the official relay, which by default gets only the push token and ids, never the banner text.
