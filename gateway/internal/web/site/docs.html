API 文档API docs

发送方用 Bot API（/bot<token>/<method>），沿用 Telegram 的命名和响应信封；手机 App 用 App API（/v1）。下面的示例都已填好这个网关的地址。Senders use the Bot API (/bot<token>/<method>), with Telegram's naming and response envelope; the phone apps use the App API (/v1). Every example below already has this gateway's address in it.

网关地址Gatewayhttps://honk.example.com

工作原理How it works

  1. App 注册自己的 APNs/FCM 推送令牌，得到 device_secret。The app registers its APNs/FCM push token and gets a device_secret.
  2. App 新建机器人，得到令牌 <bot id>:<secret>，例如 aZ3kQ9xT:Gw2K7mx…。机器人 id 是 8 位以字母开头的随机 base62 字符。The app creates a bot and gets its token, <bot id>:<secret>, for example aZ3kQ9xT:Gw2K7mx…. A bot id is 8 random base62 characters starting with a letter.
  3. 发送方调用 /bot<token>/sendMessage。网关把消息放进队列，推送只带横幅文字和 msg_id。A sender calls /bot<token>/sendMessage. The gateway queues the message and pushes only the banner text and the msg_id.
  4. 手机上的通知扩展（iOS）或 FCM 服务（Android）拉取 GET /v1/messages/:id（含卡片）并存到本地。On the phone the Notification Service Extension (iOS) or FCM service (Android) fetches GET /v1/messages/:id, card included, and stores it.
  5. App 打开时调用 GET /v1/sync 补齐漏掉的，再 POST /v1/ack。When the app opens it calls GET /v1/sync for anything missed, then POST /v1/ack.

队列里的消息 7 天后过期（HONK_MESSAGE_TTL）；组里所有设备都确认过的消息，在创建一天后删除（HONK_ACKED_KEEP）。推送失败（网络错误、超时、5xx、带 retry_after 的 429）会在 2 s、10 s、60 s 后重试，共四次。Queued messages expire after 7 days (HONK_MESSAGE_TTL); a message every device of the group has acked is deleted a day after it was created (HONK_ACKED_KEEP). A push that fails for a reason that may pass (network error, timeout, 5xx, 429 with retry_after) is retried after 2 s, 10 s and 60 s, four attempts in all.

令牌与响应Tokens and responses

令牌就在路径里：/bot<token>/<method>。方法名不区分大小写，GET 和 POST 都可以；参数放在查询串、application/x-www-form-urlencoded、multipart/form-data 或 JSON 里（JSON 中不是字符串的值，例如 data 对象，按它的 JSON 文本处理）。请求体最大 128 KB。The token is in the path: /bot<token>/<method>. Method names are case-insensitive and both GET and POST work; parameters go in the query string, application/x-www-form-urlencoded, multipart/form-data or JSON (a JSON value that is not a string, such as a data object, is taken as its JSON text). Bodies are at most 128 KB.

每个响应都是 Telegram 的信封：Every response uses Telegram's envelope:

JSON
{"ok": true, "result": …}
{"ok": false, "error_code": 400, "description": "body is required"}

时间戳是 Unix 毫秒；message_id 是整数，机器人 id 是短字符串。令牌泄露时在 App 的机器人设置里重置，旧令牌立刻失效。旧网关（schema v1）发的 4:Gw2K7mx… 这类整数 id 令牌在重置前仍然可用。Timestamps are Unix milliseconds; message_id is an integer and a bot id a short string. If a token leaks, reset it in the app's bot settings: the old one stops working at once. Tokens with integer ids from older gateways (schema v1), like 4:Gw2K7mx…, keep working until they are reset.

getUpdates

GET · POST/bot<token>/getUpdates

长轮询取卡片请求，返回更新数组。更新只在内存里保留 15 秒；小于 offset 的更新视为已确认并丢弃。设置了 webhook 时返回 409 Conflict。Long-polls for widget queries and returns an array of updates. Updates are kept in memory for 15 s; an update below offset is confirmed and dropped. Answers 409 Conflict while a webhook is set.

import json, os, urllib.parse, urllib.request

api = "https://honk.example.com/bot" + os.environ["HONK_TOKEN"]
call = lambda m, **p: json.load(urllib.request.urlopen(f"{api}/{m}?" + urllib.parse.urlencode(p)))["result"]

offset = 0
while True:
    for u in call("getUpdates", offset=offset, timeout=50):
        offset = u["update_id"] + 1
        q = u["widget_query"]
        call("answerWidgetQuery", widget_query_id=q["id"], data="ok: " + q["data"])

answerWidgetQuery

GET · POST/bot<token>/answerWidgetQuery

在 15 秒内回答一个卡片请求：widget_query_id 和 data（0–1024 字节）。回答只会送到发起请求的那台设备，卡片里 request() 的 Promise 得到它。超时、已回答或属于别的机器人的请求返回 400。Answers a widget query within 15 s: widget_query_id and data (0–1024 bytes). The answer goes only to the device that asked, where the card's request() Promise resolves with it. A query that timed out, was answered already or belongs to another bot is a 400.

机器人与通知Bots and notifications

机器人在 App 里创建，每个都是手机上一个独立会话，有自己的名字、头像和默认级别；Android 上每个机器人一个通知渠道。Bots are created in the app; each is a chat of its own on the phone with its own name, avatar and default level, and on Android its own notification channel.

silent=true 完全不弹横幅。同一个 id 的消息在手机上原地替换，适合"构建中 → 成功"这类状态。搜索、保留期限、导出导入都在手机本地完成，网关不参与。silent=true shows no banner at all. HTML 卡片HTML cards

卡片使用 Telegram HTML widget 的格式（Bot API 10.4）。网关按白名单清洗：保留文本与结构、表格、details、button、a、style、data: 图片、内联 SVG 和内联 <script>；删除外部脚本和模块脚本、on* 事件属性、表单控件、外部资源，以及会加载东西的 CSS（@import、url() 等）。加密消息的卡片网关看不到，App 解密后用同一份白名单再清洗一次。Cards use Telegram's HTML widget format (Bot API 10.4). The gateway cannot see an encrypted card, so the app cleans it with its own copy of the whitelist after decrypting.

端到端加密End-to-end encryption

在 App 的机器人设置里按机器人开启。App 生成 32 字节密钥并显示在令牌旁边；之后这个机器人的明文 sendMessage / editMessageData 都会被拒绝（400）。发送方需要令牌和密钥。Turn it on per bot in the app's bot settings. # pip install cryptography
import base64, json, os, urllib.request
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

url, token, key = "https://honk.example.com", os.environ["HONK_TOKEN"], os.environ["HONK_KEY"]
b64d = lambda s: base64.urlsafe_b64decode(s + "=" * (-len(s) % 4))
b64e = lambda b: base64.urlsafe_b64encode(b).rstrip(b"=").decode()

content = {"title": "Deploy", "body": "api v1.8.2 is live"}
nonce = os.urandom(12)
# AESGCM returns ciphertext || tag; the bot id (before the ":") is the AAD
sealed = AESGCM(b64d(key)).encrypt(nonce, json.dumps(content).encode(), token.split(":")[0].encode())
body = json.dumps({"ciphertext": b64e(nonce + sealed), "level": "active"}).encode()

req = urllib.request.Request(f"{url}/bot{token}/sendMessage", body, {"Content-Type": "application/json"})
print(urllib.request.urlopen(req).read().decode())
import { createCipheriv, randomBytes } from "node:crypto";

const { HONK_TOKEN: token, HONK_KEY: key } = process.env;
const content = { title: "Deploy", body: "api v1.8.2 is live" };
const nonce = randomBytes(12);
const cipher = createCipheriv("aes-256-gcm", Buffer.from(key, "base64url"), nonce);
cipher.setAAD(Buffer.from(token.split(":")[0])); // the bot id
const sealed = Buffer.concat([nonce, cipher.update(JSON.stringify(content)), cipher.final(), cipher.getAuthTag()]);

const res = await fetch(`https://honk.example.com/bot${token}/sendMessage`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ ciphertext: sealed.toString("base64url"), level: "active" }),
});
console.log(await res.text());
它防什么，不防什么：防网关运营者、数据库泄露、推送中继、Apple 和 Google 读到内容；不防被攻破的发送方或设备，也不防流量分析——网关仍然知道哪个机器人在什么时候收到多大的消息。解密后的大小和格式限制由 App 检查。What it covers: the gateway operator, a leaked database, a push relay, Apple and Google cannot read the content. It does not cover a compromised sender or device, or traffic analysis: the gateway still sees which bot gets a message, when and how big. The app enforces size and format limits after decrypting.

设备组Device groups

配对过的设备组成一个设备组，共享机器人和队列。每条消息（包括编辑和删除）推给组里每台能收推送的设备；每台设备有自己的同步游标和确认水位，消息要等最慢的那台确认后才会清理。Paired devices form a device group that shares bots and the queue. Every message, edits and deletes included, is pushed to every device of the group that can take a push; each device keeps its own sync cursor and ack watermark, and cleanup waits for the slowest one.

在旧手机的 设置 → 设备 → 添加设备 生成 26 位配对码（10 分钟内有效，只能用一次），新手机输入即可。网关只看到由配对码经 HKDF-SHA256 派生出的 link_id 和加密后的令牌包，看不到配对码本身。按 IP 限制尝试次数，防止猜码。On the old phone, Settings → Devices → Add device shows a 26-character pairing code (good for 10 minutes, once); enter it on the new phone. The gateway only sees a link_id and the sealed token bundle, both derived from the code with HKDF-SHA256, never the code. Claims are limited per IP so a code cannot be guessed.

命令行Command line

网关二进制同时是发送工具。honk（或 honk serve）运行网关，其他子命令以一个机器人的身份调用网关。HONK_URL / HONK_TOKEN 也可以用 --server / --token 或 ~/.config/honk/config.json 提供。退出码：0 成功，1 网关或网络失败，2 用法错误。The gateway binary is also a sender tool. honk (or honk serve) runs the gateway; the other subcommands talk to a gateway as one bot. HONK_URL / HONK_TOKEN can also come from --server / --token or ~/.config/honk/config.json. Exit status: 0 success, 1 gateway or network failure, 2 usage error.
